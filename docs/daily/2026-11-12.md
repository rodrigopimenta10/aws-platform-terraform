## Warm-up: two questions from earlier notes
<details><summary>1. Someone deletes the lock-related config and two engineers run <code>apply</code> at the same moment against the S3 state. What can go wrong, and which setting prevents it? (from <a href="2026-11-10.md">2026-11-10</a>)</summary>

Both read the same state and the later write silently overwrites the earlier one, which corrupts Terraform's record of reality. `use_lockfile = true` makes the S3 backend write a `.tflock` object with a conditional write, so only one run wins.

</details>

<details><summary>2. Why can a caller add an <code>owner</code> key through <code>extra_tags</code> and still not change the owner tag? (from <a href="2026-11-09.md">2026-11-09</a>)</summary>

The standard tags are merged last, and with `merge` later maps win, so `extra_tags` can only add new keys.

</details>

## What it is, in plain terms
Private subnets have no public IP addresses, so nothing in them can reach the internet, even to download a
container image. A **NAT gateway** (Network Address Translation) is a managed AWS appliance that fixes this. It
sits in a public subnet, owns an **Elastic IP** (a fixed public address) and forwards connections that
private resources start, rewriting the source address. Replies come back through it, but nobody outside can
start a connection inward. It lives in one **availability zone (AZ)**, so if that AZ fails, the gateway goes with it.
It also bills every hour it exists (about $33 a month in us-east-1) plus per GB processed.

## How it works
One number controls everything:

```hcl
nat_count = var.enable_nat_gateway ? (var.single_nat_gateway ? 1 : var.az_count) : 0
```

The EIPs and gateways use `count = local.nat_count`. NAT gateway `i` goes in public subnet `i`. Each private
route table then gets a default route:

```hcl
resource "aws_route" "private_nat" {
  count          = var.enable_nat_gateway ? var.az_count : 0
  route_table_id = aws_route_table.private[count.index].id
  nat_gateway_id = aws_nat_gateway.this[var.single_nat_gateway ? 0 : count.index].id
  destination_cidr_block = "0.0.0.0/0"
}
```

In single mode every table points at gateway 0. In per-AZ mode table `i` points at gateway `i`. This is why M1.1
made one private route table per AZ. Isolated subnets get nothing, on purpose.

## Why it's built this way
- **Per-AZ by default**: an outage in one AZ should not take down egress everywhere. The $73 a month saved by
  a single NAT is a deliberate opt-in, not something you get by accident.
- **Two booleans, not one enum**: `enable_nat_gateway = false` is a real case (sandboxes, the live drill),
  and `single_nat_gateway` is ignored then.
- **Live drill stays free**: `live/stacks/vpc` now sets `enable_nat_gateway = false`, because the new default
  would otherwise add NAT gateways to a stack documented as costing $0.
- Alternatives (NAT instances, VPC endpoints that avoid NAT for AWS traffic) are in ADR 0004. Endpoints come in M1.3.

## How it's tested
Mock-provider `plan` tests check the counts for per-AZ, single, two-AZ, disabled, and "single ignored when
disabled". The Moto tests apply the module and assert each NAT sits in its own AZ's public subnet, each
private route points at its own AZ's gateway (and at the one shared gateway in single mode), and that
disabling NAT leaves no private default route. Moto emulates NAT gateways and EIPs, so no gaps to report.

## Interview questions
<details><summary>1. Why must a NAT gateway be in a public subnet?</summary>

It needs a route to the internet gateway to forward traffic out. A NAT gateway in a private subnet would have no path to the internet.

</details>

<details><summary>2. What is the trade-off between one NAT and one per AZ?</summary>

One NAT is about a third of the price but is a single point of failure for egress and adds cross-AZ data charges. One per AZ costs more but isolates failures to one AZ.

</details>

<details><summary>3. How can you reduce NAT data charges for traffic to S3?</summary>

Use an S3 gateway endpoint: traffic to S3 then stays on the AWS network, bypasses the NAT gateway and is free of NAT processing charges. That is M1.3.

</details>
