## What it is, in plain terms
A **VPC** (Virtual Private Cloud) is your own isolated network inside AWS, with an IP range you choose,
written as a **CIDR block** (`10.0.0.0/16` means "all addresses starting `10.0`", about 65,000 of them). You
divide it into **subnets**, each living in exactly one **availability zone (AZ)**, a physically separate data
center in the region. Spreading across AZs keeps you running if one fails.

What makes a subnet "public" is only its **route table**, the list of rules saying where traffic goes. A
public subnet has a rule sending `0.0.0.0/0` (everything) to an **internet gateway**, the door to the internet.
A private subnet has no such rule. An isolated subnet is private and will never get an outbound path either.

## How it works
The VPC range is first cut into four equal tier blocks, and each tier's subnets come out of its own block:

```hcl
tier_blocks = {
  private  = cidrsubnet(var.vpc_cidr, 2, 0)
  public   = cidrsubnet(var.vpc_cidr, 2, 1)
  isolated = cidrsubnet(var.vpc_cidr, 2, 2)
}
subnet_cidrs = { for tier, block in local.tier_blocks :
  tier => [for i in range(var.az_count) : cidrsubnet(block, local.tier_newbits[tier], i)] }
```

`cidrsubnet(prefix, newbits, n)` adds `newbits` to the prefix length and returns the n-th block. On a `/16`,
2 bits gives four `/18`s, and 2 more bits gives `/20` subnets. The subnets then use `count` so index `i` is AZ `i`.
Private route tables are one per AZ:

```hcl
resource "aws_route_table" "private" {
  count  = var.az_count
  vpc_id = aws_vpc.this.id
}
```

## Why it's built this way
- **Tier blocks prevent overlap by construction.** The alternative, one flat `cidrsubnet` numbering with a
  different offset per tier, works until someone changes a size variable and two tiers collide.
- **Private is largest** because EKS pods take VPC IP addresses.
- **Isolated tier** has no internet route at all, which is stronger than relying on a security group.
- **Per-AZ private route tables** so M1.2 can pick one shared NAT or one per AZ by changing route targets only.
- **Default security group emptied**, and no auto-assigned public IPs.
- **Cost:** everything here is free. NAT gateways (M1.2) are what start costing money.
- **checkov skips, with reasons:** flow logs (`CKV2_AWS_11`) arrive in M1.4, and the AZ data source pin
  (`CKV_AWS_394`) is skipped on purpose because the module takes the first N zones by name.

## How it's tested
Mock-provider `plan` tests check the exact default address plan, that big `newbits` values still never
overlap, the two-AZ variant, routing, EKS tags, and every validation (bad CIDR size, non-network form, AZ
count, newbits, subnets smaller than `/28`, cluster name). The Moto test applies the module and checks
subnets, route tables, the internet route and the emptied default security group. Two things I hit: with
`plan`, the default security group's rule sets are unknown until apply, so that check moved to the Moto test;
and comparing a tuple output to a list literal prints a type warning, so the unit test compares joined strings.

## Interview questions
<details><summary>1. What makes a subnet public?</summary>

A route to an internet gateway in its route table (and resources with public IPs). Nothing about the subnet itself.

</details>

<details><summary>2. Why one private route table per AZ?</summary>

NAT gateways live in one AZ. Per-AZ tables let each AZ use its own NAT for resilience, or all share one to save money, without restructuring.

</details>

<details><summary>3. How does <code>cidrsubnet("10.0.0.0/16", 4, 2)</code> work out?</summary>

It adds 4 bits to the prefix (`/20`) and takes block number 2: `10.0.32.0/20`.

</details>
